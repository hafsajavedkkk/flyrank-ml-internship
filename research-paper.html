Prioritizing Search Opportunities with Machine Learning

A decision-support study of historical search-performance signals

Author: Hafsa Javed

Project: FlyRank Machine Learning Internship Capstone

Abstract

This project investigates whether historical search-performance signals can help identify page/query observations that deserve content or SEO review. The analysis uses the FlyRank Internship Warehouse dataset and compares a transparent baseline with a machine-learning approach under a consistent validation design. The resulting system produces ranked opportunities intended to help a human reviewer decide what to inspect first. Results are interpreted as observed decision-support evidence rather than proof that a recommended change will improve future performance.

1. Introduction and Problem Statement

Search-performance datasets can contain a large number of page/query observations, making it difficult for a reviewer to inspect every opportunity manually.

The research question for this project is: Can historical search-performance signals be used to identify and rank page/query observations that may deserve content or SEO review?

The purpose is prioritization. Instead of treating every observation equally, the system provides a ranked queue that allows a human reviewer to inspect potentially useful opportunities first. The output is decision support and does not automatically modify or publish content.

2. Data

The analysis uses data from the FlyRank Internship Warehouse. The unit of analysis is a page/query observation within a consistent analysis window.

Features are restricted to information that could reasonably be available at the decision moment. Client-identifying information, future-window information, target-derived fields, and known leakage fields are excluded from model inputs.

Results in this paper are presented in aggregate or using public-safe examples. No private client names or private queries are intentionally included.

3. Methodology

I first constructed a transparent baseline so that the machine-learning approach had an honest benchmark to beat. The baseline and model were evaluated using the same target, data, metric, and validation logic.

Features represent information available at prediction time. The workflow also included checks for label-derived information and future-data leakage.

An honest grouped or time-aware validation approach was used where appropriate to reduce the risk of learning patterns that would not be available in a realistic future decision.

Model performance is interpreted relative to the baseline rather than assuming that additional complexity automatically produces a better decision system.

4. Results: Model vs Baseline

The baseline and machine-learning model were compared under the same validation design. This comparison asks whether the model provides useful predictive signal beyond the simpler rule.

Baseline Transparent reference rule used as the minimum benchmark.
Machine-learning model Evaluated against the same data, split and metric to test whether additional predictive signal was observed.

The detailed executed results and model outputs are retained in the project notebooks. The reported comparison should be read as measured performance on the observed validation data rather than a guarantee of future outcomes.

5. Limitations and Honest Framing

This analysis is observational and cannot establish causation. A high-priority recommendation therefore does not prove that changing a page will cause its performance to improve.

Historical search patterns may also change. Search systems, competitors, content, user behaviour, and traffic composition can all shift over time.

The analysis represents a specific observation window and model errors remain possible. Recommendations should therefore be interpreted as directional decision support and reviewed by a person before action is taken.

6. Ranked Recommendations

The final output is a ranked review queue. Higher-ranked items should be inspected first, but the ranking does not authorize automatic changes.

Priority Reason Code Suggested Action
1 HIGH_IMPRESSIONS_LOW_CTR Review title and search snippet
2 HIGH_IMPRESSIONS_LOW_CTR Review content alignment
3 POSITION_OPPORTUNITY Inspect ranking opportunity
4 POSITION_OPPORTUNITY Review page relevance
5 MONITOR Monitor before taking action

Each recommendation requires human review of context, data quality, business relevance, and the proposed action before any change is made.

8. Intended Use and Human Review

This system is intended to prioritize observations for human inspection. It should not automatically publish, delete, or materially change content.

A reviewer should verify the underlying data, page context, business relevance, and recommendation before acting.
